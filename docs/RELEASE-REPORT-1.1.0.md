# Raport wydania YouTube Link Collector 1.1.0

Autor projektu: **ProGraMajster**. Rozwinięto istniejący projekt i jego pojedynczy plik instalacyjny, bez dodatkowych bibliotek. Nie zmieniano rzeczywistej instalacji ani danych użytkownika. Paczka 1.0.0 pozostaje osobnym archiwum.

1. **Przyczyna błędu eksportu.** Kod 1.0.0 używał `require("fs").promises`, następnie `fs.open`. W aktualnym BetterDiscord `require("fs")` zwraca polyfill callback, który nie eksportuje ani promises, ani open. Argument funkcji zapisu jest więc undefined, a pierwsze wywołanie odtwarza dokładnie wyjątek undefined/open. Potwierdzono tę niezgodność w źródłach BetterDiscord i teście regresyjnym. Zrzut użytkownika potwierdza komunikat oraz 126/126/0, lecz nie zawiera stosu i wersji klienta; nie wykonano diagnozy identycznego procesu Discorda użytkownika. Poprzednia fixture miała promises i dlatego maskowała rzeczywisty problem. [Źródło fs](https://github.com/BetterDiscord/BetterDiscord/blob/133bc83b6bae998a321615a77e15b94956265d12/src/betterdiscord/polyfill/fs.ts), [loader require](https://github.com/BetterDiscord/BetterDiscord/blob/133bc83b6bae998a321615a77e15b94956265d12/src/betterdiscord/polyfill/index.ts).

2. **Naprawa zapisu i importu.** Kontrola dostępnych funkcji wybiera callback filesystem BetterDiscord albo pełne Node fs.promises. Callback zapisuje UTF-8 do własnego temp z flagą wx, odczytuje go kontrolnie, wykonuje rename i sprawdza treść docelową. Pełny Node zachowuje FileHandle/fsync. Sukces jest ogłaszany po ukończonym zapisie; anulowanie canceled/cancelled/null jest ciche. Błędy filesystemu pozostają prawdziwymi błędami, bez czyszczenia kolekcji. Brak API lub awaria native IPC umożliwia Blob/download, potem schowek, potem ręczne kopiowanie pełnej treści. Przekazanie do pobrania jest nazwane przekazaniem, nie potwierdzonym zapisem Electron. Import obsługuje callback/promises, BOM, limit rozmiaru i selektor File.text; po błędzie natywnego importu dostępny jest osobny przycisk przeglądarkowy. Kanał i struktura są walidowane przed potwierdzanym zastąpieniem.

3. **Analiza wyszukiwarki.** Referencja BetterDiscord dokumentuje bieżący searchId, zapytanie, filtry i offset, lecz nie stabilny paginator ani iterator wszystkich wyników. Wewnętrzne opcjonalne wyniki/loading i DOM/React props pozostają zmienne. Czytamy je tylko po wykryciu właściwego kształtu, w zakresie przypisanego kanału. Numer strony pochodzi z rozpoznanej kontrolki lub deklaracji użytkownika; nie dzielimy offsetu przez stałe 25. Sam numer, licznik albo brak nowych linków nie potwierdzają przetworzenia ani końca. [Stores](https://docs.betterdiscord.app/discord/modules/data-stores), [funkcje wyszukiwania](https://support.discord.com/hc/en-us/articles/115000468588-How-to-Use-Search-on-Discord).

4. **Automatyczna nawigacja.** Nie wdrożono jej jako dostępnej funkcji: nie potwierdzono stabilności w aktualnym zalogowanym kliencie ani dopuszczalności automatyzowania zwykłego konta. Oficjalne zasady zabraniają automatyzacji kont poza API bot/OAuth2; BetterDiscord nie jest oficjalnym systemem rozszerzeń Discorda. Wdrożono zaakceptowany w wymaganiach tryb półautomatyczny: użytkownik klika strony, plugin zbiera i zapisuje. Nie ma tokenów użytkownika, private endpointów, klikającego bota ani fałszywego wyboru „automatycznie”. [Polityka kont automatycznych](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots).

5. **Nowe funkcje.** Historia wielu zakresów i ich filtrowania/sortowania; odrębne strony zaobserwowane, widoczne i potwierdzone; stabilizacja dwóch odczytów po minimum 900 ms, kontrola bieżącej zawartości/seen, podpisy ID i brak podwójnego zaliczania; luki/recheck i timeout 20 s; zatrzymanie po zmianie zakresu/kanału; Pauza, bezpieczny Start, ręczne oznaczenie i potwierdzenie; historia zakresów w panelu, ostrzeżenia MEE6/dat/domen, diagnostyka; kopiowanie pojedynczego i 100 wyświetlanych linków; opcjonalna sprawdzona kopia JSON co 5 min na wskazaną ścieżkę tylko w tej sesji. Eksport zachowuje całą kolekcję bez względu na filtr/stronę panelu. Parser nadal uwzględnia watch, youtu.be, Shorts, Live, Music, embed i playlisty.

6. **Checkpointy i migracja.** Schemat 1 i aktywne klucze checkpoint/state-a/state-b pozostają bez zmian. Nowe searchTracking v1 jest dodatkiem; jego brak w 1.0.0 daje pustą historię, zachowując rekordy i seen. Oryginalne envelope/pointer są kopiowane z kontrolą odczytu pod legacy-1.0.0 przed pierwszym zapisem nowej wersji. Błąd kopii blokuje nadpisanie starych banków. Banki nadal rotują z readback i wskaźnikiem; oba uszkodzone blokują zapis. W razie pustego cache dodatkowa kontrola własnego pliku konfiguracji chroni przed ukrytym błędem całego JSON, jeśli wymagane API są dostępne. Historia mieści się w budżecie 24 MiB, z dodatkowymi granicami 64 zakresów/8000 stron/4 MiB; przekroczenie wycofuje metadane strony, zachowując rekordy. Import zachowuje legacy; jawny Reset usuwa wskazane dane. Restore przerywa dawny running, nie uruchamia sam nawigacji ani nie fabrykuje pięciu stron z pięciu partii starego zapisu.

7. **Walidacja.** 103/103 testy Node bez pominięć, kontrola składni 8 plików i granic transportu, 24/24 sprawdzenia zwykłego panelu oraz 8/8 dużego panelu na atrapach. Test pliku wygenerowanego oryginalnym kodem 1.0.0 zachowuje dokładnie 126 rekordów i oryginalne envelope. Syntetyczny model ma 3300 unikalnych zasobów / 6600 wystąpień na stronach o zmiennej wielkości: TXT/CSV/JSON zawierają dokładnie 3300/6600 zgodnie z trybem, JSON odtwarza wszystkie 6600. Sprawdzono rzeczywisty filesystem Node w obu wariantach i wszystkie formaty, a w przeglądarce rzeczywisty download Blob (130 URL) oraz wybór pliku/import (126 rekordów). Fizyczny schowek nie został niezależnie potwierdzony. Pełny log i rozróżnienie dowodów: [VALIDATION](VALIDATION.md).

8. **Znane ograniczenia.** Rzeczywisty BetterDiscord 1.1.0, jego dialogi/fs/stores, kontowy zbiór 126 i pełny kanał 2554 nie zostały uruchomione podczas tych prac. Informacje 26/76/126 są potwierdzeniem użytkownika dla 1.0.0. Przy brakujących danych klienta konieczne są własny opis/numer i sprawdzenie strony. Ręcznej deklaracji oraz kompletności indeksu nie da się potwierdzić przez plugin; sam DOM może być częściowo zamontowany. Nawet wszystkie potwierdzone strony i obie domeny pozostawiają kolekcję lokalną INCOMPLETE. Zmiany wyników na nieodwiedzonej ponownie stronie mogą nie zostać wykryte. Callback BD nie ma fsync; BdApi readback nie jest dowodem trwałego flush. Snapshoty i zapis blisko limitów mogą opóźniać UI; rzeczywisty Electron wymaga osobnego pomiaru. [Ograniczenia](LIMITATIONS.md), [protokół manualny](MANUAL-TEST.md).

9. **Bezpieczna aktualizacja 126 linków.** Stop i zapis w 1.0.0 → zamknięcie Discorda także w zasobniku → kopia **YouTubeLinkCollector.config.json obok pluginu w Plugins Folder**, starego pluginu i katalogu danych BetterDiscord → podmiana tylko plugin.js z zachowaniem nazwy → restart → kontrola 126/126/0 → natychmiastowy JSON i sprawdzenie pliku → Wznów/Start. Nie usuwaj konfiguracji i nie klikaj Reset. Jeśli liczby się nie zgadzają, zachowaj kopie i zatrzymaj pracę. Przykładowe liczniki służą instrukcji weryfikacji, nie potwierdzają aktualizacji konta.

10. **Zbieranie około 2554 wyników.** Usuń filtr MEE6 i niepotrzebne daty/has, pozostaw dokładny in: kanału i stałe sortowanie. Ręcznie otwórz pierwszą stronę youtube.com i Wznów. Poczekaj na stabilny odczyt; w razie braku numeru użyj pełnego własnego opisu i aktualnego numeru. Przy visible-only sprawdź/przewiń całą stronę przed Potwierdź odczyt strony. Przechodź kolejne strony, uzupełniaj wskazane luki i zapisuj JSON/kopie. Po ostatniej dostępnej stronie zmień zakres na youtu.be, Wznów i powtórz bez Reset. W razie limitów dziel daty na osobne, opisane zakresy. Stop, JSON do odtworzenia, potem TXT/CSV w wybranym trybie. 2554 to licznik wiadomości Discorda, nie obietnica 2554 unikalnych filmów; duplikaty i wielolinkowe wiadomości zmieniają wynik. [Pełna instrukcja](../README.md).

Wydanie obejmuje plik **YouTubeLinkCollector.plugin.js**, dokumentację, testy, fixture i narzędzia w ZIP 1.1.0, manifest SHA256 wszystkich plików oraz SHA256 ZIP. Instalacja wymaga wyłącznie pojedynczego plugin.js. Kryterium kwalifikacji realnego klienta pozostaje protokół manualny; wykonane tu testy przygotowują wydanie do testów użytkownika.
